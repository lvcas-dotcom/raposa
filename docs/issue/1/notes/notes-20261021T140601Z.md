# Análise inicial

## O que a análise mediu

- O projeto adota arquitetura hexagonal, linguagem de domínio, organização por
  produto, testes de comportamento e registros por issue.
- Go 1.27.1 disponível via proto. O shim Go do sistema usa snap e falhou no sandbox.
- npm confirmou REA 6.7.0; instalado com lockfile e scripts de instalação desativados
  em `~/.local/share/rea-tool`.
- Documentação pública descreve contexto, ferramentas, revisão, verificação e memória;
  essa descrição não revela implementação ou qualidade observada.

## Decisões

- [usuário] Projeto independente em `Área de trabalho/Lucas/Projetos/open-rabbit`.
- Entrada com issue local #1 e branch `feat/1-revisor-local`: não há servidor Git definido.
- Go, stdlib, CLI primeiro. Ports pertencem ao application; adapters implementam.
- Provedor semântico por comando explícito, sem fixar modelo ou usar credencial existente.
- Duas passagens: candidatos e refutação. Evidência e linhas validadas localmente.
- Baseline Go conservadora serve para exercitar o fluxo e medir, sem afirmar paridade.
- REA é instrumento de pesquisa; não é dependência runtime do revisor.

## Guardrails

Sem commit/push/PR e sem publicar mensagens. O revisor lê Git
sem checkout e não executa build, hooks ou testes do alvo. O comando de modelo é
configuração confiável fornecida por quem opera; dados do alvo são não confiáveis.
Respostas de modelo exigem evidência literal presente no snapshot e localização no diff;
isso verifica rastreabilidade, não prova a conclusão semântica.
